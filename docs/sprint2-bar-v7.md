# Sprint 2 registered bar v7 (2026-10-19, after vote round 6) - NOT frozen

**Little north star:** the operator drops `upload_items.txt` (Amazon.de links) into `upload_items/`, starts the app with `start.bat`, clicks ONE button, and every link becomes at most one eBay listing on the target the app is set to (Sandbox -> sandbox eBay, Production -> live eBay), without duplicates.

## Two freeze points (changed in v2)
1. **Commitment freeze** (operator's freeze): plan, this bar, card list. Implementation T1-T5 happens AFTER it; that is not a violation.
2. **Measurement freeze**, written by T0/T6 as `sprint2-freeze.json` before run A: tested source SHA (clean worktree), fixture SHA, expected-table SHA, baseline-census SHA, price-snapshot SHA, and the same four for the C-set (file path, fixture SHA, expected-state SHA, price-snapshot SHA). A one-byte edit to any C-set artifact makes the pre-run check exit nonzero; the receipt prints all of them. A pre-run check exits 0 at that SHA and nonzero after a one-byte edit. Any change to those files, or to source between runs A and C, is INCONCLUSIVE (rule 2). The receipt records both freeze points.

## Fixture and registration (S2-T0; all committed before the measurement freeze)
- 20 lines from `bulk/000001.txt`: 12 distinct expected-publishable ASINs (E = 12), 3 alias/repeat lines of E ASINs, 2 junk lines, 2 margin-FAIL ASINs, 1 control ASIN that already has a published sandbox listing. |E| < 10 registered = INCONCLUSIVE.
- **C-set (run C only, outside E and p):** a second registered file of 4 distinct ASINs, disjoint from the 20 lines, with its own expected states: all 4 are registered expected-publishable (4 x PUBLISHED, clear margin in the price snapshot). The price-flip rule applies to the C-set too: a flipped C-set row makes C2 INCONCLUSIVE, not NOT_MET. The census before run C shows zero C-set offers/items.
- A terminal-state/reason enum, and per line `expected_state` + `expected_reason` for runs A, B and C separately. **Run B expectation depends on run A:** a row that ended `ERROR_RETRYABLE` in run A has the run B expectation {PUBLISHED, ERROR_RETRYABLE}; every other row keeps its fixed expectation. This rule is in the expected table, frozen in `sprint2-freeze.json`, and a unit test with one retried row yields MET/WEAK, not NOT_MET.
- **Price snapshot:** the Amazon price/availability used for each row's margin decision, recorded per ASIN with fetch timestamp, host and field; the receipt prints snapshot vs runtime price for every row. A row whose margin outcome flips relative to the snapshot is a *price-flipped row*: its state/reason difference is exempt from the mismatch check in verdict rule 1, it receives no success credit in p, and the original |E| stays the denominator. Up to 2 flipped rows are tolerated; 3 or more make the measurement INCONCLUSIVE unless a higher-priority violation exists. A duplicate, production request, purchase or unknown offer is NOT_MET regardless of flips. Worked cases for E=12 (MET needs p >= 10): 0 flips and p=10 MET; 2 flips and p=10 MET; 2 flips and p=9 WEAK; 3 flips INCONCLUSIVE; 1 flip plus a duplicate NOT_MET.
- **Baseline census (hashed):** all remote sandbox inventory items and offers, paginated, for every SKU, taken before run A. It includes the smoke listing `DD-SMOKE-TEST-1` (`tools/sandbox_smoke.py`) and the control listing.
- **Control listing:** T0 creates it (or names an existing one) and registers its SKU/inventory item, offerId and listingId. It is tied to the control ASIN.
- **SKU -> ASIN rule:** SKU `DD-<ASIN>` maps to that ASIN. The app also writes the marker `ASIN:<ASIN>` into the inventory item description, so an offer under any other SKU is attributable. Classification is census-anchored: **baseline** = any offerId/itemId present in the hashed pre-run census regardless of its SKU (the smoke listing `DD-SMOKE-TEST-1` need not follow `DD-<ASIN>`); E / control / C-set = attributed by the SKU rule or the marker; **unknown** = absent from the census and unattributable. A unit test with three remote offers (E, control, non-DD baseline) yields zero unknown and zero duplicate flags; an injected unregistered offer yields unknown. A test with an alternate-SKU fixture proves an injected second offer for an E ASIN is detected.

## Sandbox identity pin
The freeze records the sandbox API host, marketplace/site ID and app target name; the receipt prints host and site for every request. A run with a mismatching site (for example EBAY_US injected) refuses before publish and creates 0 offers/items. C5's authorized-path attempt appears exactly once in the interception log, naming the sandbox host and the frozen site ID, with zero outbound sockets opened.

## Measurement (Sandbox only; the first live use is a separate operator decision)
Start with a clean sandbox for E (census shows zero E offers/items). Launch through `start.bat`, click once (**run A**), click again after completion (**run B**, identical re-click), and **run C** below. After each run wait >= 60 s and read the remote sandbox state twice (paginated census, not local files); the two reads must be identical. Receipt `sprint2-run.json`: both freeze points, per-row state, request hosts, timestamps, remote offer/item IDs, the census classification.

**Run C (separate scenario on the C-set, no reset of E):** the app is started with a deterministic fault-injection flag that hard-exits in the window after a remote publish is accepted and before its durable local acknowledgement. The kill happens after at least one C-set publish is accepted with other C-set rows still pending (receipt: flag, exit code, timestamps, pending-row count > 0). Restart and resume with the same frozen source SHA, only the fault-injection flag removed. The census after resume must show, for every C-set ASIN, exactly one offer/item, and the killed row's offerId and listingId (after-kill census, before restart) unchanged after resume. The after-kill census is read twice, >= 60 s apart, before restart, and both reads must be identical. The receipt shows the accepted offerId and a pending-row count > 0 before the kill, and the gap between the price snapshot and run A. The receipt records the census before run C (zero C-set offers), after the kill and after resume.

**Deadline:** each run has a registered wall-clock limit of 20 minutes (frozen in `sprint2-freeze.json`); for run C the limit applies to each segment (before kill, after restart) separately, and the receipt prints both elapsed times and the limit applied. Exceeding it is NOT_MET, with the pending-row state dumped to the receipt.

**p is counted from the run-A census** (after the settle wait and two identical reads). Runs B and C are judged by their own controls.

## Verdict (top to bottom, first match wins)
1. NOT_MET on any: actual request to a production eBay host (a refused or intercepted attempt that sends no outbound request is not one); Amazon cart/purchase action; an ASIN with more than one offer, or more than one item, across all SKUs (per the SKU->ASIN rule; one item plus one offer is the healthy state); an offer classified `unknown`; a row whose state or reason differs from its registered expectation for that run, except (i) an ordinary E row ending `ERROR_RETRYABLE`, or `UNKNOWN` because the pre-retry remote read was ambiguous and no second publish was sent, which only lowers p, and (ii) a price-flipped row (fixture section), whose difference is exempt and earns no credit; a failed control below.
2. INCONCLUSIVE if no violation is seen but: |E| < 10; a frozen file or source SHA changed after the measurement freeze or between runs A and C; the duplicate claim rests only on local files or mocks; two remote reads differ; a required scenario never exercised its action (a publishing scenario with zero publish requests; C5 is judged by rule C5 below, not by this clause); price flips as above.
3. Otherwise p = number of E targets, excluding price-flipped rows, with a published sandbox item in the run-A census (the census alone decides; a row's local state is not consulted): p >= ceil(0.8 |E|) MET; ceil(0.6 |E|) <= p < ceil(0.8 |E|) WEAK; anything else NOT_MET.

## Required controls (outside E and p)
- C1 run B creates 0 new offers/items for ASINs already published in run A and no ASIN with more than one offer; a row that ended `ERROR_RETRYABLE` in run A may be retried in run B, but there is at most one offer in total for that ASIN across A and B (exactly one if the ASIN is reported PUBLISHED; zero is permitted for an ASIN that ended `ERROR_RETRYABLE` in both runs with no remote offer, and a test with such a row yields MET/WEAK when p qualifies): the remote read (the same paginated census call T6 uses, not a mock) and its census offerId are logged before any run-B retry, and an existing offer is adopted, never republished.
- C2 run C: every C-set row accounted for, exactly one offer/item per C-set ASIN, the killed row's offerId AND listingId (read from the after-kill census, before restart) unchanged after resume, the kill log line naming the same SKU/ASIN, 0 duplicates; the receipt row is (ASIN, post-kill offerId/listingId, post-resume offerId/listingId, EQUAL).
- C3 the control ASIN is skipped; its offer/item IDs unchanged.
- C4 a concurrent second click while a run is active is refused (HTTP 409) or attaches to the same run; 0 extra writes.
- C5 Production gate, by interception (no real request): the run request is submitted, the server refuses it (target Production without both flags, or without the server-side `LIVE <n>` confirmation bound to the file hash), and the interception log shows 0 outbound calls; the authorized path is exercised through interception up to the point just before the network; switching the target during a run aborts the run. C5 uses a hard network deny: the interception layer is deny-by-default: only sandbox hosts are allowed, any other resolved host (including a host alias or redirect stub) raises, and the log shows 0 outbound production calls. C5 exercises two refusal subcases: (i) Production without the flags; (ii) Production with the flags but a missing or mismatched `LIVE <n>` or file hash. The log shows two refusals. C5 passes with zero outbound requests.
- C6 an injected ambiguous publish outcome (timeout) keeps the row UNKNOWN until an authoritative remote read; the request log shows no second publish before reconciliation. Fails closed under delayed visibility. C6 runs as an interception test against the app's eBay client with the injected timeout; it never changes the A/B/C census.

## Live path rules (built in this sprint, used only by operator decision)
Target snapshot per run; Production requires `EBAY_AUTOMATION_ENABLED`, `EBAY_ALLOW_LIST`, and a typed `LIVE <n>` confirmation showing seller, count, file hash; live batch cap `EBAY_LIVE_BATCH_MAX` (default 10, larger files run the first 10 and ask again); stop after 3 consecutive eBay errors; missing/negative margin never publishes.

## Not claimed
Sandbox success is not live behaviour: this sprint proves sandbox behaviour and an intercepted Production gate only. Not claimed: profitability, Amazon data rights, live seller-account behaviour, listing quality at scale, scale beyond 20 rows, variation-group publishing, price stability beyond the snapshot.
