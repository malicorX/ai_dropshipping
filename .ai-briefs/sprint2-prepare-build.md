## Deliverables
A. **Prepare mode.** `UploadJobManager.start(mode="full"|"prepare")` (default "full" = unchanged behaviour). `POST /api/upload-items/start` takes an optional JSON body `{"mode":"prepare"}`; no body = full. In prepare mode a row runs: existing check -> fetch -> evaluate -> margin gate -> AI draft (+ the deterministic variation-label title patch, which must now be saved INTO the stored draft via `save_listing_draft`) and then ends in a new terminal row state `prepared`. **It must make zero eBay calls** (no `stage_unpublished`, no `publish_offer`, no oauth/network to eBay). Add `prepared` to ROW_STATES/terminal states and to the counters. Rows already published OR already prepared (candidate has a draft title and no published state) end as `skipped_existing` with reason "haben wir schon (vorbereitet)" BEFORE any Amazon fetch, so the LLM is not called twice. OAuth sign-in is not required in prepare mode.
B. **Overview.** New module `dropship_desk/prepared.py` with `list_prepared()`: every candidate with a non-empty draft title whose listing state for the current env is not `published`. Per item: asin, title, ebay_price, amazon_total, margin (as the evaluation stored it), `prepared_at` (draft/candidate updated_at), `ebay_status` (`none` = not on eBay yet, `unpublished` = offer staged), offer_id, `age_days`. `GET /api/prepared` returns `{target_env, live_disabled, items}`; read-only, local only, no network.
C. **Publish selected / all.** `UploadJobManager.start_publish(asins)` and `POST /api/prepared/publish` body `{"asins":[...]}` (empty or missing list -> 400; unknown or already published ASINs are reported as `skipped_existing`/`not_prepared`, never an error for the batch). Same single-flight lock, sandbox pin, target-change abort, durations and status/stop endpoints as the upload job (reuse `/api/upload-items/status`; add `"mode"` to status). Per row: **re-check price first** (re-fetch Amazon + `run_evaluate(save=True)`; a failed margin gate -> `rejected` with the reasons and the row is NOT put live; the AI draft is NOT regenerated), then `stage_unpublished(asin)` and `publish_offer(asin)`. Production: 403 `LIVE_UPLOAD_DISABLED` exactly as for start; `NOT_SIGNED_IN` 409 as for start.
D. **UI.** In `ui/src/App.tsx`: (1) on the Upload tab a second button "Only prepare (no eBay)" next to "Start upload from file". (2) A new tab "Prepared" with a table of `GET /api/prepared` (checkbox per row, select all/none, title, price, margin, status, age), a button "Put selected live (n)" and "Put all live", disabled in production with the reason shown, and progress via the existing status polling (the same progress table with the Time column).
