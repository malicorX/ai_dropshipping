## A. Automatic retry of transient errors
Measured: about 1 in 3 Amazon fetches ends `AMAZON_UNREACHABLE ... ERR_CONNECTION_RESET` after the 3 inner attempts; today the operator must click again. After the main pass of any run mode (full, prepare, publish), rows whose state is `error` AND whose reason starts with `AMAZON_UNREACHABLE` are re-queued for up to 2 extra passes (constant `MAX_RETRY_PASSES = 2`), each pass preceded by a pause (`RETRY_PASS_PAUSE_SEC = 30`, module constant, patchable in tests; sleep in small steps so Stop is honoured within ~1 s). Rules: only `AMAZON_UNREACHABLE` rows retry (not not_found, rejected, margin, eBay errors, variation_parent); a Stop request or an abort (target change / systemic abort) ends retrying at once; a retried row resets its state to queued, keeps a `attempts` counter (new field, exposed in `to_dict`, starts at 1), and its duration/timing is restamped per attempt; final failure after the last pass stays `error` with the reason prefixed "after N attempts: ". Status gets `retry_pass` (0,1,2) and `phase` shows `retrying`. The existing systemic cap (MAX_CONSECUTIVE_FAILURES in amazon/product.py) must still abort the whole run - do not change the fetch module. UI: show the attempts count in the row (e.g. "2x") and the phase.

## B. Choice of the list file
Today the file is always `upload_items/upload_items.txt` (override env UPLOAD_ITEMS_FILE). New: any `*.txt` directly inside the `upload_items/` folder can be chosen.
- `GET /api/upload-items/files` -> `{dir, default, files:[{name, size, modified, lines}]}` (sorted by modified desc; non-recursive; only `.txt`). 
- `GET /api/upload-items/preview?file=<name>`, `POST /api/upload-items/start` body `{"mode":..., "file":"<name>"}` accept a file NAME. Validation (security): name must be a bare file name (no path separators, no `..`, not absolute, no drive letters), end with `.txt`, resolve inside the upload dir and be an existing regular file; otherwise 400 `INVALID_UPLOAD_FILE` and nothing is read. Missing `file` = today's behaviour (default file / env override). The chosen file name is stored in the run state and returned in status (`file`).
- UI: a dropdown above the preview listing the files (default selected = upload_items.txt if present, else newest), remember the last choice in localStorage (try/catch), preview reloads on change, both Start buttons send the selected file; the Upload tab shows the file name of the running job.
