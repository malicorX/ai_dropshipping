## Goal (operator)
A file `upload_items/upload_items.txt` in the project root (`config.RUNTIME_ROOT / "upload_items" / "upload_items.txt"`, override env `UPLOAD_ITEMS_FILE`) holds Amazon.de links, one per line. One UI button reads it and processes every link: parse ASIN -> fetch from Amazon -> evaluate -> eBay copy draft (Ollama) -> stage unpublished offer -> publish. In SANDBOX mode the listing goes to the sandbox eBay account. In PRODUCTION mode the whole feature REFUSES (HTTP 403, code `LIVE_UPLOAD_DISABLED`) BEFORE any network call: the operator forbade any live eBay write for now. No Amazon cart/purchase/login code anywhere.

## A. Backend (new module `dropship_desk/upload_items.py` + endpoints in api.py)
1. `read_upload_file(path) -> list[Row]`: ignore blank lines and `#` comments; extract the ASIN with `asin.extract_asin` from each URL line; keep the original line; dedupe by ASIN (second occurrence becomes row state `duplicate_in_file`, not processed); a line without a valid ASIN becomes state `rejected` reason `no_asin`. Missing file -> a clear error (`UPLOAD_FILE_MISSING`, 404) naming the path.
2. A job class modelled on ENRICH_JOB (thread, single-flight: a second start while running returns HTTP 409 with the current run id; `status()` returns run id, target env, started_at, rows with `state`, `reason`, `offer_id`, `listing_id`, `item_url`, counters). Sequential, one ASIN at a time. States: queued, fetching, evaluated, drafted, staged, published, skipped_existing (already published for this env: do not touch eBay), not_found (`ASIN_NOT_FOUND` from the fetch: SKIP AND CONTINUE, never an error), rejected (hard reject / margin FAIL / variation parent: reason text), error (reason). A row error never stops the run, except systemic errors (`ChromeNotFound`, `AmazonUnreachable` failure-cap) which abort the run with the reason.
3. Per-ASIN pipeline reusing existing code, NOT re-implementing it: refactor the body of `/api/listing/generate` into a plain callable (for example `generate_draft(asin, ebay_price=None, amazon_total=None, title=None)` in a module both the endpoint and the job use; the endpoint must behave exactly as before, existing tests stay green). Steps: fetch offer (`fetch_product_offer`, which already has retry/pacing/cap), `run_evaluate(..., persist="always")` (use the suggested price), skip with `rejected` if it fails the gate, download images + draft, then `ebay.listing.stage_unpublished(asin)` and `publish_offer(asin)`. Duplicates: before staging, if the local listing state is already `published` in this env -> `skipped_existing`; otherwise rely on the SKU `DD-<ASIN>` reuse in `_create_or_update_offer` so a second click never creates a second offer.
4. Target gate: read `config.ebay_env()` once at start and store it in the run; if it is `production` refuse as above; if the env changes during a run, abort the run (state `aborted_target_changed`). Also require `oauth_connected` for sandbox, else 409 `NOT_SIGNED_IN`.
5. Endpoints: `POST /api/upload-items/start`, `GET /api/upload-items/status`, `POST /api/upload-items/stop`, `GET /api/upload-items/preview` (parses the file, returns rows and target env, no network).
6. Tests (`tests/test_upload_items.py`, no network, stub fetch/evaluate/draft/stage/publish): parser cases (aliases, junk, comments, in-file duplicate); production refuses with zero stub calls; sandbox happy path for 2 ASINs; one ASIN_NOT_FOUND row is skipped and the run continues; a second start while running -> 409; a second run after completion makes 0 stage calls for published rows; ChromeNotFound aborts. RED first (paste), then GREEN, then these mutants must FAIL the suite: production gate removed; not_found treated as error that stops the run; dedupe removed.
