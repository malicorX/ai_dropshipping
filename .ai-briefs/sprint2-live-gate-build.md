## Design (all must hold)
1. **Master switch, default OFF.** New config flag `EBAY_LIVE_UPLOAD_ENABLED` (env, default false; read at call time like the other flags). Live runs require ALL of: target env production, `EBAY_LIVE_UPLOAD_ENABLED` true, `automation_enabled()` true, `allow_list()` true, the production account connected. Any missing -> 403 `LIVE_UPLOAD_DISABLED` with the list of what is missing (names only). `.env.example` documents the flag as false; do NOT touch `.env`.
2. **Typed confirmation bound to the batch.** Live start/publish endpoints take `confirm` = the exact string `LIVE <n>` where n is the number of ASINs the server will process (server computes n from the file/selection, never from the client), plus a `batch_hash` (sha256 over env + sorted ASINs + for upload the file name and file content hash) that the client first obtains from a new read-only `POST /api/live/plan` ({mode, file|asins} -> {n, batch_hash, items:[asin,title,price]} - no eBay write). Wrong/missing/stale confirm or hash (file changed meanwhile) -> 409 `LIVE_CONFIRM_MISMATCH`, nothing runs.
3. **Cap.** `EBAY_LIVE_MAX_PER_RUN` (env, default 5, hard ceiling 50 in code). n above the cap -> 400 `LIVE_CAP_EXCEEDED`.
4. **Live-run pin (inverse of the sandbox pin).** A live run pins the transport to PRODUCTION for its lifetime (`pin_production_for_live(True/False)`, try/finally as the sandbox pin), and `ensure_write_target_allowed` then BLOCKS sandbox hosts and any write if the env flipped; sandbox runs keep blocking production exactly as today. A live run and a sandbox run can never overlap (single-flight already; add a test). Target switch or token env mismatch mid-run aborts like `aborted_target_changed`.
5. **Price re-check is mandatory in live** (upload mode already evaluates; publish mode re-checks at the prepared price). Live also requires margin pass; variation parents rejected; items already published on production are `skipped_existing` (separate production state files).
6. **Audit log.** Every live run appends one JSON line per row (ts, run_id, asin, sku, state, offer_id, listing_id, price, reason) plus a start line (n, batch_hash, cap, who=local) to `data/live_audit.jsonl`; a failed append must abort before the next eBay write.
7. **Kill switch.** Stop works as today; additionally setting the flag false (re-read per row) aborts the live run before the next write (`aborted_live_disabled`).
8. **UI.** Upload and Prepared tabs: when target = production and the flag is on, the buttons become "Live: plan..." -> shows the plan table (n, total, cap, first items) and a text field where the operator must type `LIVE <n>` exactly; the final button stays disabled until it matches; a red banner "PRODUCTION - real listings" is shown while a live run is active. When the flag is off the UI shows the reason and no live button. `npm run build` + `npm test`.
